# 拉取后风险项修复设计

## 背景

本次修复针对提交 `e479858` 拉取后识别出的五个风险点：

- Node 版本声明与 `lint-staged` 版本要求不一致。
- 根目录 `prepare` 脚本可能无法解析 Husky。
- 菜品分类标签从 Taro `ScrollView` 改为普通横向滚动后，小程序端兼容性不确定。
- 个人中心积分明细请求失败时与空数据状态混淆。
- 依赖安装脚本对 `.npmrc` 和锁文件变化的判断过于粗略。

## 目标

- 继续支持 Node 18，最低版本明确为 `>=18.12`。
- 保留提交前增量 ESLint 检查，不降低工程化能力。
- 保持现有页面视觉与交互，不做额外重构。
- 让积分明细区分加载、空数据和失败状态。
- 让依赖安装脚本能识别 `package-lock.json` 变化，并避免陈旧 `.npmrc` 导致源配置失效。

## 非目标

- 不升级项目最低 Node 版本到 20。
- 不重构点单页、菜品页或个人中心整体结构。
- 不调整后端接口、数据库或 Go 服务端代码。
- 不执行 Git 提交或推送。

## 方案

### Node 与 lint-staged

根项目 `engines.node` 调整为 `>=18.12`。前端 `lint-staged` 固定到 `15.5.2`，不用 `^`，避免后续安装自动升级到要求 Node 20 的主版本。

### Husky 初始化

Husky 作为根目录 `prepare` 脚本的直接依赖，应安装在根项目 `devDependencies` 中。前端仍保留 `lint-staged`，提交钩子继续进入 `fanda-app` 并只检查暂存的前端源码文件。

### 菜品分类滚动

菜品类型标签恢复使用 Taro `ScrollView scrollX`，保留当前吸顶搜索和内部列表滚动结构。这样 H5、微信小程序、抖音小程序都使用 Taro 官方横向滚动组件。

### 积分明细状态

新增积分明细加载状态，区分：

- `idle`：未加载。
- `loading`：正在请求。
- `success`：请求成功，可为空列表。
- `error`：请求失败，展示“加载失败，点击重试”。

加载中禁止重复请求。失败后保持展开面板，用户点击错误区域可重试。

### 依赖安装判断

前端依赖是否已就绪同时比较 `fanda-app/package.json` 与 `fanda-app/package-lock.json`。任一文件晚于 `node_modules/.package-lock.json`，都重新安装。

npm 源初始化不再只凭 `.npmrc` 存在就跳过。安装脚本每次执行源初始化步骤，由 `setup-npm-registry.js` 快速探测并刷新配置。`--force` 仍保留强制执行全部步骤的语义。

## 验证

- 运行根目录脚本测试。
- 运行前端 ESLint。
- 执行 H5、微信、抖音三端构建。
- 验证根目录 `prepare` 可解析 Husky。
- 检查 Git 状态，确认未提交。
